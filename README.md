#  Ticket Service Backend

Высоконагруженный бэкенд-сервис для бронирования и покупки билетов на мероприятия, спроектированный с использованием современных паттернов микросервисной и монолитной архитектуры (Clean Architecture / Enterprise Java).

---

##  Технологический стек

* **Язык программирования:** Java 21
* **Фреймворк:** Spring Boot 4.x (Web, Security, Data JPA)
* **Система сборки:** Gradle
* **База данных:** PostgreSQL 15 (с миграциями через Flyway)
* **Кэширование & Локи:** Redis 7 (распределенные блокировки для мест, хранение сессий и OTP-кодов)
* **Брокер сообщений:** RabbitMQ 3.x (асинхронная отправка уведомлений и писем через воркеров)
* **Контейнеризация:** Docker & Docker Compose
* **Документация API:** Springdoc OpenAPI (Swagger UI)

---

##  Архитектура базы данных

База данных инициализируется автоматически с помощью миграций Flyway (`V1__init_schema.sql`). Основные сущности:

1. **`users`** — Пользователи системы (хранение email, хэша пароля, ролей `ROLE_USER`/`ROLE_ADMIN` и статуса верификации `is_verified`).
2. **`events`** — Каталог мероприятий (название, описание, дата, площадка, количество мест).
3. **`seats`** — Места в зрительном зале, привязанные к мероприятиям (ряд, место, цена) с уникальным индексом на ряд и место в рамках события.
4. **`bookings`** — Заказы/бронирования мест пользователями со статусами (`PENDING`, `CONFIRMED`, `CANCELLED`).
5. **`payment_transactions`** — Платежные транзакции по бронированиям (интеграция с внешним эквайрингом через UUID).
6. **`tickets`** — Сгенерированные билеты с уникальным номером и статусом использования (`is_used`).

##  Быстрый старт (через Docker)

Для запуска приложения вместе со всей инфраструктурой (PostgreSQL, Redis, RabbitMQ) вам понадобятся установленные **Docker** и **Docker Compose**.

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/sawelyew/ticket-service.git
   cd ticket-service
   ```

2. **Подготовьте файл окружения:**
   Создайте файл `.env` на основе предоставленного шаблона `.env.example` и заполните необходимые параметры (данные для подключения к БД, почте и секретный ключ JWT):
   ```bash
   cp .env.example .env
   ```
   *(Убедитесь, что файл `.env` заполнен корректными данными).*

3. **Запустите проект одной командой:**
   ```bash
   docker-compose up --build -d
   ```

Docker автоматически соберет проект на Java 21, поднимет базы данных, применит миграции Flyway и запустит сервер.

##  Документация API (Swagger UI)

После успешного запуска приложения документация к REST API и возможность тестирования эндпоинтов доступны по адресу:
👉 **[http://localhost:8080/swagger-ui/index.html](http://localhost:8080/swagger-ui/index.html)**

### Основные модули API:

* **Auth (`/api/v1/auth`)**
  * Регистрация, авторизация (JWT Access/Refresh токены).
  * Запрос OTP-кода подтверждения почты и верификация (с фоновой отправкой через RabbitMQ).
* **Events & Catalog (`/api/v1/events`)**
  * Получение списка мероприятий с фильтрацией по дате, площадке и текстовым поиском (с пагинацией).
  * CRUD-операции для администраторов.
* **Seats Management (`/api/v1/events/{eventId}/seats`)**
  * Просмотр схемы зала и доступных мест, добавление/удаление мест (Admin).
* **Booking Management (`/api/v1/bookings`)**
  * Резервирование мест с использованием распределенного лока в Redis (TTL 10 минут).
  * Инициация оплаты и обработка банковских вебхуков (`/webhook/bank`), подтверждение брони, создание билета и снятие лока.
* **Users & Profile (`/api/v1/users`)**
  * Получение профиля текущего пользователя, просмотр активных предстоящих билетов и истории заказов.

##  Безопасность

* Защита эндпоинтов реализована с помощью **Spring Security** и JWT.
* Чувствительные данные (пароли от БД, почтовые учетные данные, JWT Secret) изолированы в `.env` файле и не попадают в систему контроля версий.
